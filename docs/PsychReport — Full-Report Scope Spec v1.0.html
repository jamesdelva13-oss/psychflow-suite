PsychReport · Spec Revision

Full-Report Scope: Ingestion, Contracts & the RIE Handoff

Extends the five-mode section system from results-section generation to complete report drafting, with source-bound reasoning contracts on every section.
v1.0 · Draft for reviewJuly 23, 2026Supersedes: results-only scope
Amendment — 2026-07-23 (D-081)

Handwritten observation notes are NOT deferred. Multimodal transcription of photographed handwritten observation notes enters at M1/M2, with a mandatory clinician verification step: the transcription is shown beside the source image and must be confirmed or corrected before any claim enters the ledger. Rationale: it is the highest-frequency self-authored input, and it is an image-in-existing-call-pattern, not an OCR subsystem. Ratified in the canonical decision trunk as D-081.

01 · Scope Change

PsychReport is a full-report writer

The clinician provides all source material — score reports, rating scales, notes, records, referral package — and PsychReport drafts the complete report. The clinician's job shifts from writing sections to reviewing, correcting, and owning the draft.

Market rationale: full-document ingestion ("drop everything in, get a report out") is now table stakes across Psynth, School Psych AI, PAR, LilyAssist, and BastionGPT. A results-section writer competes against products that draft the entire document.

Differentiation thesis Competitors run one undifferentiated model pass over heterogeneous input. PsychReport drafts the same full scope, but every sentence is contract-bound to a source. "Complete report, fully sourced" beats both "results only" and "dump and pray."
Boundary preserved Full scope means everything up to the eligibility boundary. Adverse-impact / SDI language remains exclusively in the separate Eligibility Artifacts workflow. PsychReport must refuse to generate eligibility-determinative language even when source documents invite it — this is now a stronger differentiator, not a casualty of the scope change.
02 · Ingestion Pipeline

From documents to a claims ledger

The ingestion layer is the new front door. It reuses the QA Engine monorepo's parser, intermediate representation, and entity-extraction stack — redirected from finished reports to source documents.

// pipeline stages UPLOAD any docx / pdf / image / text ↓ CLASSIFY assign document class (table below) ↓ EXTRACT scores → structured records prose → atomic claims ↓ LEDGER every claim gets: source_doc · locator · reporter claim_type · confidence ↓ GAPS missing-input report before drafting ↓ DRAFT sections generated under contracts (§03), citing ledger IDs only

Document classes

ClassExamplesExtraction target
SCORE_REPORTQ-global, PARiConnect, scoring printoutsInstrument, scale, score, CI, percentile
RATING_SCALEBASC-3, Conners-4 protocolsScores + reporter identity (parent/teacher/self)
REFERRAL_PKGRIE export, referral formsReferral question(s), concern claims
INTERVIEWParent/teacher/student interview notesReporter-attributed claims
OBSERVATIONClassroom/testing observation notesSetting, task, observed behaviors
RECORDSPrior evals, IEPs, grades, attendance, healthDated historical facts
DISTRICT_DOCTemplates, local guidanceFormatting + section constraints only

Ledger rules

  • No orphan prose. Draft sentences must cite ledger claim IDs. Anything the model wants to say that has no claim behind it is either boilerplate (from the approved template library) or it doesn't get written.
  • Reporter attribution is immutable. A claim extracted from a teacher interview can never surface as a parent report or an examiner observation.
  • Conflicts are preserved, not resolved. When sources disagree (parent vs. teacher ratings, records vs. interview), the ledger stores both; contracts govern how sections present the discrepancy.
  • Gap report precedes drafting. Before generation, the user sees what's missing per section (e.g., "no observation document; Observations section will be skipped or stubbed"). No silent invention to fill holes.
Build note Milestone 1 is score-report PDF extraction (Q-global + PARiConnect layouts), since structured scores feed both PsychReport and the QA Engine. Handwritten-note OCR is deferred; typed notes and PDFs cover the dominant workflow.
03 · Reasoning Contracts

Per-section contracts at full scope

Each section binds to one of the five modes and adds section-specific rules: which document classes it may draw from, what inference is permitted, and what it must refuse. Contracts extend reasoning-contracts.ts.

Reason for ReferralEXTRACTION-ONLY
SourcesREFERRAL_PKG only (RIE export preferred)
InferenceNone. Restate referral questions and concerns as documented; no elaboration, no softening.
RefusesAdding concerns not in the referral; foreshadowing findings.
Background & HistoryEXTRACTION-ONLY
SourcesRECORDS, INTERVIEW, REFERRAL_PKG
InferenceChronological ordering and grouping only. Every fact dated and reporter-attributed.
RefusesCausal narrative ("likely due to…"), developmental interpretation, filling timeline gaps.
ObservationsATTRIBUTED-REPORT
SourcesOBSERVATION, INTERVIEW
InferenceBehavioral description only; setting and task context required per claim.
RefusesTrait language ("is anxious") in place of observed behavior; merging observers.
Validity StatementTWO-LAYER VALIDITY
SourcesSCORE_REPORT (validity indices), OBSERVATION (testing behavior)
InferenceExisting two-layer model unchanged: instrument-level indices + session-level conditions.
RefusesDeclaring results valid when either layer lacks data.
Results (per instrument)SCORE-BOUND NARRATIVE
SourcesSCORE_REPORT, RATING_SCALE
InferenceCurrent v3 narrative behavior. Domain-based prose per formatting conventions; only scales with provided scores; no age/grade equivalents.
RefusesCross-instrument synthesis (reserved for Summary); diagnostic language.
Summary & Clinical ImpressionsBOUNDED-SYNTHESIS
SourcesPrior sections only — may cite only claims already established upstream in this draft
InferenceConvergence/divergence across sources; explicit answer to each referral question; discrepancies named, not smoothed.
RefusesNew facts; eligibility-determinative or adverse-impact language (hard boundary → Eligibility Artifacts workflow); diagnosis beyond the referral scope.
RecommendationsCONSTRAINED-GENERATION
SourcesSummary claims + curated recommendation bank
InferenceEach recommendation must trace to a finding; bank entries adapted, not free-generated.
RefusesPlacement or eligibility recommendations; recommendations orphaned from findings.

The anti-sycophancy stance carries over: contracts instruct the drafting model to surface weak or conflicting evidence rather than produce a fluent, agreeable narrative. The QA Engine then audits the finished draft as an independent second system — generation and audit never share a pass.

04 · RIE → PsychReport Handoff

The referral package interface

RIE's completed intake becomes PsychReport's first-class input — the suite integration story. The handoff is a versioned JSON export; PsychReport treats it as a pre-structured REFERRAL_PKG that bypasses classification and extraction.

// referral_package v0.1 (shape sketch) { "package_version": "0.1", "referral_questions": [ { "id": "rq1", "text": "...", "domain": "..." } ], "concern_claims": [ { "id": "c1", "text": "...", "reporter": "teacher|parent|clinician", "capture_mode": "async_form|live_interview", "source_item": "bank_item_id|freeform" } ], "prior_supports": [ ... ], "student_ref": { "mode": "identified|aliased", "fields": { ... } }, "qa_flags": [ ... ] // from RIE QA Engine }

Interface rules

  • Capture-mode agnostic. capture_mode travels with each claim, honoring the multi-modal vision — async form-fill and live interview capture produce the same package shape, so PsychReport never assumes async-only input.
  • Referral questions are load-bearing. They flow into Reason for Referral verbatim and become the checklist the Summary contract must answer — the mechanism preventing the "answered the test results but missed the referral concern" failure the market critiques.
  • Identity handling matches the firewall decision. student_ref.mode is identified in district/DPA deployments and may be aliased in solo-practitioner mode — consistent with the tiered firewall (Option 4). No mapping-storage layer is required in identified mode.
  • RIE QA flags surface in the gap report. Unresolved intake flags (incomplete teacher bank items, scrub advisories) appear before drafting so the clinician resolves them upstream.
05 · Sequencing

Build order

M1

Score-report PDF extraction

Q-global + PARiConnect layouts → structured score records. Shared foundation for PsychReport and QA Engine; validates the parser redirection.

M2

Claims ledger + gap report

Prose extraction for INTERVIEW / OBSERVATION / RECORDS classes; ledger schema; pre-draft missing-input report.

M3

Contract extension

New section contracts into reasoning-contracts.ts; Summary's prior-sections-only citation rule; eligibility-boundary refusals tested against adversarial source docs.

M4

RIE handoff v0.1

Referral package export from RIE Phase 1; PsychReport import; referral-question → Summary checklist wiring.

M5

Full-draft assembly

End-to-end: upload set → gap report → complete draft under contracts → QA Engine audit pass on output.
