## P33 (candidate) · Render-layer purity — an RIE pre-emission self-check

**Decision:** D-047 (2026-07-23). Adopted as an **RIE-side pre-emission
self-check**, to land in the v0.7 spec. **Not a QA Engine rubric row** (see the
rationale — this is the load-bearing part of the ruling).

**Rule.** The rendered draft contains only report prose. Prohibited anywhere in a
block body: tier labels (`T0` / `T1` / `T1-obs` / `T2` / `T3`), P-rule citations,
item IDs (e.g. `CORE-008`, `IMP-001`), instrument or spec version strings,
branch/screener state, and drafter commentary about routing decisions. All of
that lives in the IR, the reproducibility pin, or the P14a pass — homes that
already exist outside the document. RIE checks its own output for these literals
before emitting.

**Root cause it closes.** P29 specifies the render form for `T1-obs`, but no rule
prohibited spec metadata from appearing in rendered output generally. The
commitment that tier "lives in the IR, not re-derived from prose" governs where
tier is *stored*, not whether it leaks into the document. The prohibition was
assumed, not written — and it is the one class of rule that cannot stay implicit,
because the drafter is a model with the spec in context and a natural pull toward
showing its work.

**Reproducibility-pin carve-out (must be explicit in the rule).** The italic
reproducibility-pin subtitle (e.g. *"Mathematics = bare negative (P22); hands-on
relocated to Other Information"*) **is metadata by definition and is exempt.**
State this in the rule text or the next drafter will strip the pin.

**Why RIE-side, not a QA rubric row (D-047 rationale — do not lose this).**
Metadata literals like `T1-obs` or `P29` can only appear in a document **RIE
itself drafted**. A QA check for them would be tuning QA against our own output —
the self-certification failure D-035 warns against — and QA's job is to review
*arbitrary district reports*, which RIE did not write. Worse, the originally
proposed regexes (`\bP\d{1,2}\b`, `v\d+\.\d+`) throw false positives on ordinary
district prose: "P1" as a program name, "v2.0" as a plan version, page refs, etc.
The check belongs where the output is known-provenance: RIE's own emission path.

**If it ever earns a QA row:** advisory-tier only, and narrowly scoped to
`T1-obs`-style tier literals — never the broad P-rule / version-string regexes.
That is the ceiling, ratified now so the scope can't creep later.

*(Candidate lint, for the RIE self-check only — not QA: regex inside block bodies
for `T1-obs` and the bare tier tokens `\bT[0-3]\b`. The broader `\bP\d{1,2}\b` /
`v\d+\.\d+` patterns are explicitly rejected as false-positive-prone.)*
